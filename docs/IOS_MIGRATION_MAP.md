## Design changes
- **Photo walls (2026-09-30).** The owner uploaded 11 fluted-glass backgrounds and kept four: Blue 1, Blue 3, Sand 1, Sand 4 — the only walls now; the gradient walls (Sage, Cream, Honey, Mist) are retired. Settings → Appearance picks one. Default: Sand 1 (owner's pick). Preference key `fa.wall.v3`. A 28 % white wash keeps ink text on the wall legible; card glass carries a 60 % white frost on top of the glass so text on cards reads over the photos. Originals in `design/backgrounds/`.

- **Home, owner's layout (2026-09-30).** One check-in a day, in the evening (digestion is inside it): the Home square next to "Log a meal" is the evening check-in only (`EveningCheckinCard`; the morning/evening carousel is gone). On it: the marker curves and pills — mood, sleep, energy, calmness and, in green, digestion (`gutOverall`); no panes, no button (the card itself opens the check-in). Today's focus card and the Today's digestion card are off Home; the two squares are followed directly by today's actions (`PlanTodayCard`). Apple Health on Home is its readings as charts (`HealthCharts`, shared with the Health page: activity — steps, distance, active energy, exercise — last night, heart & breathing, body, workouts); before it is connected, the Connect invitation. Messages card unchanged. The functional score hero (crown + pillar lines) is off Home — Home is for meals, the check-in and the actions, a place to understand and act rather than a scoreboard; the scores stay in Trends (`FunctionalScoreCrown`). The morning check-in reminder is retired like midday (never planned; stale requests cleared by `apply()`; its row is gone from Settings → Notifications). Still there: the morning check-in screen itself, and Today's focus computed from it (its card is off Home).
- **Home = my health plan first (owner, 2026-09-30).** Top to bottom: `HealthPlanCard` ("My health plan" / "Mon plan de santé": the clinician's `objective_line`, the current phase + plan week, the patient-visible `care_plan_goals`, and the items flagged `is_weekly_focus` as priorities — clinician words only; taps through to the full plan; loading / error / no-plan states) → `PlanTodayCard` ("Today's actions": the current moment's first; an earlier moment's skipped action is no longer carried as catch-up, done ones stay) → meal + evening check-in squares → doctor signpost when raised → "Worth a look together" → messages. Goals and priorities ride the Habit Loop read, each soft. Apple Health's charts moved to Trends; Trends' check-in button opens the evening check-in. No "what influences you" card (would be AI-derived — a medical-device line the practice won't cross). Next: the plan page layout, a habits place in Trends to correct a skipped action, and notifications that open the matching action card (with its video/explanation).
- **Action cards + the plan page (owner, 2026-10-02, after the approved mockup).** Every row of "Today's actions" opens `ActionCardView`: the practice's action card around the clinician's habit — type · moment · duration, the image, the gentle / standard / further versions (today's face preselected), a demonstration video (opened outside the app) and a YouTube keyword (YouTube search, nothing embedded), the numbered steps, the why, the linked library article (`Route.read`), and Done / Not today (Done = the same check-off as Home; Not today records nothing). Breathwork cards get a wordless pacer with a timer for the card's duration (the steps say how to breathe — rule 6). A habit without a card opens on its own words. Cards are `habit_bank` rows authored in CLINICAL → Action cards (live iPhone preview, OpenAI draft of empty fields, publish gate) and read LIVE through `habits.habit_bank_id` (owner decision: an edit the practice publishes reaches every member who has the card); English/French with fallback to the other language. Migration `supabase/migrations/20261002_action_cards.sql` (applied on CM OS 2026-10-02): `habit_bank.card_kind`, `duration_min`, `how_md_fr`, `general_why_fr`, `published_at/by`; `habits.habit_bank_id`; links in `resources` as a typed list (video · youtube · article). Drafts are `active = false`, so RLS and the focus engine never see them. `CarePlanView` is now "My health plan": objective + goals, the journey (week N of M, each phase done / in progress / coming up, the current one's summary), this week's priorities, My actions (a Monday–Sunday strip — full / part / none / nothing due / ahead, each its own shape — then the actions by moment, each opening its card), the plan in detail (the domain sections), and To read for your plan (the articles the active actions link, once each). Logic in `ActionCardLogic` / `PlanPageLogic`, tested. Not yet: the blurred "book your call" state with the booked call's date (CLINICAL already serves `GET /api/patient-app/appointments`; `FA_API_BASE_URL` is still empty), notification deep links to a card, habit corrections in Trends.
- **Ideas parked (owner, 2026-09-30).** Screen time (evening/morning use vs mood): Apple's Family Controls entitlement is for apps whose primary purpose is family controls or digital wellbeing, and forbids sending usage off the device — for now the practitioner asks members to look at Settings → Screen Time in consultation. HealthKit candidates: time in daylight, caffeine, alcoholic drinks. Blood glucose: not via HealthKit — a dedicated CGM integration (Abbott or another provider) later.

## Server-side moves required (the PRD §41 debt the audit exposed)
1. `lib/health/*` score stack (crown composite, vitality/metabolic/nutrition/recovery/longevity, gut composites) → `member_scores(p_day)` RPC or edge function; `nb_score_tips` already assumes such keys.
2. `lib/checkin/red-flags.ts` → evaluated server-side on check-in write (mirror of what `q1-complete` already does for Q1).
3. `lib/{movement,recovery,mind}/day{3,4,5}.ts` → scored inside `movement-report`/`sleep-report`/`mind-report` instead of trusting client numbers.
4. `lib/access/entitlement.ts` 3-day discovery window → DB rule (`expires_at` at grant time).
5. `lib/report/*` six inline-copied modules → single source in the edge function (already server-side; the client copies can be deleted once native reads `nb_report_content` only).
6. Fragile write shapes → RPCs: `member_save_profile`, `member_log_meal`, `member_submit_checkin`.
